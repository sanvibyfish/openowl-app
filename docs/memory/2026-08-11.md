## 03:40 (debug) — git 子进程 SIGBUS crash 排查 + 修复

### 背景

用户报告"第一下启动好像 crash 了"。排查 `~/Library/Logs/DiagnosticReports/` 只有一条 `git-2026-08-11-033246.ips`：

- **crash 的是 git 子进程**（SIGBUS，`cmd_status → refresh_index → ce_modified_check_fs → index_mem`），openOwl 主进程在同一时刻（03:32:45.264）以 `exit(1)` 退出（launchd 记录、无 .ips、`applicationWillTerminate` 未执行），11s 后用户重开正常。
- git 用的 Xcode 自带 2.50.1（`/usr/bin/env git` 按 PATH 解析；xcode-select 指向 Xcode 时 `/usr/bin/git` 就是 Xcode 的 git）。
- SIGBUS 根因：`git status` 正在给工作区文件算哈希时文件被截断（内核报 `cluster_pagein past EOF`）。当时用户的 `tsx audit-globalword-zh-pilot.ts` 正在往 `thai-learn-web` 项目的 `.audit-cache/` 写文件（pgrep 里 pid 40860 至今仍在跑）。
- openOwl 对同一仓库并发跑 2–3 个 git（FileExplorer status + Git 面板 status + log），FileExplorer 后台刷新 5663 节点。
- exit(1) 在全部源码里找不到 `exit()` 调用（ghostty main.swift 未编入 release 二进制），来源待仪器定位。

### 修复（4 处）

1. **`AppExitMonitor.swift`（新增，Shared/）**：`atexit` 钩子 + 致命信号 handler，退出时把回溯写进 `~/Library/Logs/openOwl/exit.log`（POSIX write，async-signal-safe），信号处理后重新 raise 保留 .ips。接入 `openOwlApp.init()` + `applicationDidFinishLaunching`。
2. **固定 git 路径**：`GitExecutable.resolvedPath`（`/usr/bin/git` → homebrew → PATH 兜底），启动时选择并写日志；`runGit`/`fileData` 不再走 `/usr/bin/env git`。
3. **status 串行化**：`GitCommandGate` 按标准化 working directory 给 `git status` 加锁，FileExplorer 与 Git 面板不再并发跑 status；diff/log 保持并发（FIFO 阻塞测试依赖并发语义）。
4. **信号退出重试**：status/diff/log 若被信号杀死自动重试一次（150ms 间隔）；写操作不重试。

- Release 测试构建失败为既有问题（test target 在 Release 下 `Unable to find module dependency: 'openOwl'`，scheme TestAction 仅配置 Debug），与本次改动无关。

## 06:50 (bugfix) — File Explorer 重命名 Enter/Esc/失焦无效

- **根因**：`OutlineTreeCellView.configure(isRenaming:)` 在 `reloadItem`/`reloadData` 期间**同步调用** `window?.makeFirstResponder(nameField)`——此时 cell 尚未挂进 NSOutlineView 的视图层级，makeFirstResponder 返回 false，TextField 从未获得焦点。于是 Enter 仍被 `KeyableOutlineView.keyDown` 截走（触发 onEnterKey 反复进入重命名）、Esc 无人处理、点击外部没有编辑会话可取消——与用户报告完全吻合。
- **修复**（`OutlineTreeCellView.swift`）：
  1. makeFirstResponder + selectText 延迟到下一 runloop，并 guard `nameField.isEditable` 防止 cell 滚动复用后误聚焦
  2. 新增 `controlTextDidEndEditing`：失焦提交（Finder 行为），`isEditable` guard 防止 Enter 后二次提交
- 验证：Debug/Release 构建通过，423 测试全过。

## 21:30 (bugfix) — Git diff 面板 "No diff output" 卡死

- 现象（用户截图 21:26）：Git tab 选中修改文件，diff 面板显示 "No diff output" 且不恢复。
- 根因：`git diff` 成功但输出**空字符串**时，`loadDiff`/`ensureSelectedDiffIsFresh` 把空 diff 当正常结果存入 `selectedDiffText`。典型触发：文件被外部（命令行/其他工具）提交或回滚，而 app 的 status 快照还没刷新——选中项还挂在列表上，diff 却已无内容，UI 永久卡在 "No diff output"。
- 修复（`GitChangesStore.swift`，两处）：diff 结果为空时判定 change 已失效 → 清除 `selectedChange` + `refreshNow()` 刷新列表，不再停在死状态。
- 新增回归测试 `emptyDiffDropsStaleSelection`：外部 `git checkout` 回滚后 refresh，断言选中被清除。423 → 424 测试全过。
