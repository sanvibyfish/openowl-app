# 2026-08-19 工作日志

## 09:50 (debug) — Git 面板 EBADF 根因定位：DispatchIO fd 泄漏

### 现象

用户在 openOwl Git 面板看到 "The operation couldn't be completed. Bad file descriptor" 报错（"又报错了"）。日志显示自 **2026-08-19 07:39:16** 起全部 git 子进程（status / ls-files / rev-parse）启动即 EBADF，且 v1.1.6 的"重试换新 pipe"也失败——不是瞬时抖动。

### 诊断链

1. **运行实例**：`/Applications/OpenOwl.app` 1.1.6 (11)，已连续运行 1 天 13.5 小时（196 CPU 小时）。
2. **fd 表打满**：`lsof -p` 实测 **~10.9K unique pipe fd，fd 号封顶 9999**（软上限 10240），15182 条 PIPE 记录。git 每次启动都要新建 pipe → 无 fd 可用 → 启动失败。
3. **无阻塞线程**：`sample` 采样 63 线程全部空闲/等在 kqueue/PTY 上，没有线程卡在管道读取——所有 pipe fd 都是没人在读的孤儿描述符。
4. **独立复现**：按 `GitPipeDrain` 模式写 Swift 测试，50 次 `git --version` 泄漏 **100 fd（每次 2 个）**。变体测试定位：`DispatchIO.close()` 之后 dup 的读端 fd **仍然 open**——libdispatch 不关闭 fd-based 通道的 fd，cleanup handler 收到的参数是 0（不是 fd）。
5. **修复验证**：cleanup handler 中显式 `close(dup 的 descriptor)` → 200 次启动 **0 泄漏**。

### 根因

`GitPipeDrain` 把 `dup()` 的读端 fd 交给 `DispatchIO` 通道，通道 close 后从未关闭该 fd。每次 git 启动泄漏 2 fd。约 37 小时活跃开发（status 刷新等）累计 ~10.9K fd → 打满 fd 表 → 之后一切 git 启动 EBADF。v1.1.6 的重试只能扛住瞬时抖动，扛不住慢性泄漏。

### 修复

`openOwl/Services/GitService.swift` GitPipeDrain.init：`DispatchIO(...) { _ in close(descriptor) }`——在 cleanup handler（通道最后生命周期点，`close()` 内同步执行且恰好一次）显式关闭 dup 读端。加注释说明 libdispatch fd 所有权契约。

### 验证

- 独立复现：修复版 200 次启动 0 泄漏（修复前 100/50 次）
- `xcodebuild -scheme openOwl -configuration Debug build` ✅ BUILD SUCCEEDED
