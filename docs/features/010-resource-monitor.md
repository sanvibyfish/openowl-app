# FEAT-010: 进程资源异常监控

> 状态：🟡 In Progress | 创建日期：2026-07-16

---

## 1. 功能概述

openOwl 运行期间每分钟检查当前登录用户的进程，在单进程内存异常增长、内存占用过高或 CPU 长时间高负载时发送 macOS 原生系统通知。

该功能用于提前发现失控的开发工具、浏览器 Helper、构建任务或其他后台进程。当前版本只提醒，不自动结束进程。

## 2. 用户流程

1. 用户启动 openOwl，并允许系统通知权限。
2. openOwl 在后台每 60 秒采样一次当前用户的所有可访问进程。
3. 进程命中异常规则后，macOS 右上角显示发送者为 OpenOwl 的系统通知。
4. 通知包含进程名称、PID，以及当前内存、内存增长量或 CPU 使用率。
5. 同一进程的同类问题在 30 分钟内不会重复提醒。

关闭 openOwl 主窗口不会停止监控；完全退出应用后监控停止。

## 3. 技术实现

### 3.1 采样

- `proc_listallpids`：枚举系统进程。
- `proc_pidinfo(PROC_PIDTASKALLINFO)`：读取进程 UID、启动时间、RSS 和累计 CPU 时间。
- 只保留 UID 与当前登录用户一致的进程。
- 使用 `PID + 进程启动时间` 作为进程实例标识，防止 PID 复用污染历史数据。

### 3.2 告警规则

| 规则 | 阈值 |
|------|------|
| 内存占用过高 | RSS ≥ 8 GiB |
| 内存快速增长 | 最近 10 分钟相对最低点增长 ≥ 2 GiB |
| CPU 持续过高 | CPU ≥ 400%，连续 3 次采样 |
| 重复提醒冷却 | 同一进程、同类告警 30 分钟 |

CPU 百分比通过相邻采样之间的累计 CPU 时间增量计算，因此多核进程可以超过 100%。

### 3.3 通知与生命周期

- `ResourceMonitor` 由 `AppDelegate` 持有，在应用启动时开始，在应用终止时停止。
- 使用 `UNUserNotificationCenter` 发送本地通知。
- `AppDelegate` 实现前台通知回调，因此 openOwl 位于前台时也会显示资源告警。
- 告警和通知失败写入 `AppLogger` 的 `resource-monitor` tag。

### 3.4 测试

`ResourceMonitorTests` 覆盖：

- 8 GiB 内存阈值和冷却时间。
- 10 分钟内存增长判断。
- 连续 3 次高 CPU 采样。
- PID 复用隔离。
- 当前进程的真实 `libproc` 采样。

## 4. 注意事项

- 当前版本不监控 Swap，也不聚合同一应用的多个 Helper 进程。
- 当前版本不自动结束、暂停或限制异常进程，避免误伤正常的编译和模型任务。
- 当前版本没有独立 Login Item/helper；完全退出 openOwl 后不会继续监控。
- 如果用户关闭 OpenOwl 的系统通知权限，异常仍会写日志，但不会显示通知横幅。
