# openOwl v1.1.8 Release Notes

> **Status**: 🟢 Ready | **Notes Ready**: 2026-10-11 | **Released**: — (DMG built, not yet tagged/published)
>
> v1.1.7 was never tagged or published; everything in this file — including what was
> drafted as v1.1.7 — ships together here.

Workspace and permission fixes: file explorer rows are no longer clipped from the
left, ⌘P Quick Open works the first time you press it, the app actually restores its
sandbox access to `~/Documents` at launch, and the log file survives being deleted
underneath the app.

## Bug Fixes

### File explorer rows no longer clipped from the left

- Selecting a deeply-indented file made AppKit's `scrollRowToVisible` pan the
  outline's clip view horizontally to reveal the overflowing cell, shoving every
  shallower row left so leading glyphs and icons disappeared behind the panel
  edge. A `TreeClipView` now pins the horizontal scroll origin to 0 — a file
  tree truncates names and never pans sideways.
- The outline column also stopped tracking the panel width, leaving a dead
  strip on the right (`sizeLastColumnToFit` runs once, `autoresizesOutlineColumn`
  is off by design). The column is now re-pinned to the outline view's real
  width on layout, change-guarded.

### Quick Open (⌘P) works before the file index exists

- The dock defaults to the Git tab, and the file index is only built once the
  Files tab has been opened. `presentQuickOpen` bailed out when the index was
  empty, so ⌘P silently did nothing in that state. The panel now opens
  immediately and fills in on its own when the background scan lands
  (`refreshQuickOpenIfPresented()` runs at the end of `refresh()` /
  `refreshFullOnly()`).
- Quick Open now targets the caller's active project
  (`fallback ?? self.projectURL`), so switching projects no longer answers ⌘P
  with the previous project's files when the Files tab was never reopened.

### Quick Open (⌘P) actually keeps keyboard focus

- The panel appeared over the terminal but never took first responder from the
  ghostty `NSView`, so typing, ↑/↓ and Escape went to the shell — Quick Open
  looked broken and stray keystrokes ran commands. The search box is now an
  AppKit `NSTextField` (`QuickOpenField`) that calls `makeFirstResponder`
  explicitly once attached, retries for 500ms, and routes ↑/↓/Return/Escape
  through its delegate.
- Root cause of the steal: SwiftUI reparents the terminal wrapper when overlay
  chrome is inserted, and `TerminalNSView.viewDidMoveToWindow` refocused itself
  unconditionally. A new `TerminalFocusPolicy` blocks that reclaim while a text
  field or field editor owns the responder.
- Escape is handled by the app's key monitor while the panel is up, so it
  closes the panel instead of clearing the shell's input line.

## Other Fixes

- **Security-scoped bookmarks are now actually restored at launch.** The
  restore loop in `ProjectStore.load()` sat before the UserDefaults-migration
  branch while the normal branch `return`ed early, so a healthy `openowl.json`
  skipped it entirely. Access to TCC-protected parents (`~/Documents`, …) then
  existed only while the user happened to add a project during that session, and
  vanished the moment it was removed — surfacing as `~/Documents` flipping
  between readable and `Operation not permitted` for everything the terminal
  spawned (a GitHub Actions runner could not read its own
  `.credentials_rsaparams`, nor exec `run-helper.sh`). Restore now runs once in
  `init`, after every load path has produced its project list, and
  `BookmarkStore.startAccessing` is idempotent so a double start can't leak the
  previous session.
- **The log file survives being deleted underneath the app.** `AppLogger` kept
  one `FileHandle` for the process lifetime; once the directory was removed
  (cleanup tools, manual deletes) every write went to an unlinked inode —
  "succeeding" while the log silently stopped existing on disk until restart.
  Each write now compares the handle's inode against the path and reopens
  (recreating the directory) when they diverge.
- **Single View menu.** `installViewMenu()` created its own `NSMenu` titled
  "View" while SwiftUI's `WindowGroup` already contributed one, so the menu bar
  showed `… Terminal View View Window …`. The Terminal / Git Changes / File
  Explorer / Quick Open items are now inserted at the top of SwiftUI's existing
  View menu, and re-asserted idempotently on activation in case SwiftUI rebuilds
  its menus.
- **Hardened-runtime entitlement for Apple Events.** `tccd` logs repeatedly
  reported `service: kTCCServiceAppleEvents requires entitlement
  com.apple.security.automation.apple-events but it is missing for
  responsible={com.openowl.app}`. Because the built-in terminal's children are
  attributed to openOwl, any `open …`, link click, or tool run from the terminal
  turned into a permission prompt naming openOwl. The entitlement (plus an
  `NSAppleEventsUsageDescription`) is now declared in `project.yml`; macOS can
  present a real, grantable consent prompt instead of failing the check.

## Removed

- The **Teammates** panel (right-dock third tab, Claude/Codex/Pi session
  scanners) added during this cycle was pulled before release. The dock is back
  to Files / Git. The design is archived in
  `docs/archive/FEAT-012-teammates.md` for a future revisit; the 17 scanner unit
  tests were removed with it.
