# openOwl v1.1.1 Release Notes

**Release Date**: 2026-07-30

Workspace UI and reliability release. v1.1.1 introduces the compact Project Rail and process resource alerts, strengthens editor reload correctness and state preservation, and fixes terminal keyboard routing, worktree archive races, and Right Dock resize behavior.

---

## New Features

### Compact Project Rail

The previous wide project sidebar has been replaced by a 48pt icon rail that keeps the terminal as the main workspace.

- Project monograms switch the active project; clicking the selected project opens its main/worktree session list.
- Roots with open terminal tabs are promoted while preserving the persisted root order.
- Switching back to a root restores its most recently selected main/worktree session.
- Free terminals, unread terminal badges, project creation, worktree creation, and Claude incident status remain available from the rail.

### Process resource alerts

openOwl now samples processes owned by the current user once per minute and sends native macOS notifications for unusually high memory, rapid memory growth, or sustained high CPU usage.

The initial rollout is alert-only: it does not terminate or throttle processes. Alerts use per-process cooldowns, distinguish PID reuse by process start time, and continue while the app is running with its main window closed.

## Bug Fixes

### Editor tab did not refresh when the underlying file changed

An already-open editor tab reused its in-memory `NSTextStorage` every time the file was selected again. If another process changed the file on disk, openOwl kept showing the stale buffer until the tab was closed and reopened.

**Fix:** Each tab now tracks a disk signature (`mtime + size + inode/fileIdentifier`). Re-opening the active file or switching back to an inactive tab compares the stored signature with the current file and reloads the tab when the file changed. Dirty tabs are explicitly protected: if the user has unsaved edits, openOwl keeps the in-memory buffer and logs a `reload-skip reason=dirty` event instead of clobbering work.

The signature lookup uses `FileManager.attributesOfItem(atPath:)` rather than cached `URLResourceValues`, because tests showed resource values could stay stale immediately after a write.

Every file URL now has an independent read request identity. Before applying a result, openOwl rechecks the request, project session generation, and current disk signature, so an older async read cannot replace newer content. Tab activation is tracked separately from loading: finishing a reload for file A can no longer clear file B's pending activation and leave B blank.

Active text reloads publish a fresh `NSTextStorage` and rebuild the editor around it. Mutating the existing storage in place would bypass the editor's own text-replacement path and leave its undo manager pointing at the pre-reload content, so a later undo could replay an out-of-bounds range. The caret is clamped to the new buffer and restored; scroll position and focus are not carried across a reload.

### Large-file progress overlay could stick to the wrong tab

The editor's heavy progress overlay was global state. When large-file load/restore/close work was superseded by another tab operation, stale overlay text could survive beyond the file it belonged to and make the editor feel blocked.

**Fix:** Progress text is now associated with a specific file URL and is only cleared by the matching operation. Closing, clearing, evicting, and failed restore paths all remove the matching progress state.

### Editor context changes and saves could lose or overwrite unsaved work

Project/worktree/free-terminal actions previously changed selection before dirty-tab auto-save failure was known. Save paths also did not consistently reject a write when the file had changed externally.

**Fix:** `ProjectStore` now calls the editor's synchronous preflight before any switch or removal side effect; a failed save means the whole action does not happen, including no terminal-namespace switch after a pane veto. The `activeKind` observer includes free-terminal A → B changes. ⌘S, close-tab save, and context preflight all share the same disk-signature conflict check and preserve the dirty buffer when the signature changed or is unavailable.

`RightDockView` also stays mounted while collapsed, so File Explorer tabs and dirty buffers are not destroyed. Closing active tab A selects adjacent tab B through the normal switch/reload path. Open failures remove the failed tab from the persisted session; restore failures remove only the in-memory attempt so a later restore can retry. Automatic restore/reload rejects ordinary text at or above 50 MB and images above 50 MB; missing file size/signature data no longer falls back to zero.

Separately, a newly opened tab that fails to read or decode now clears its owned pending activation and loading state, so the existing editor is not left behind an overlay.

### File copy/cut/drop failures were silent

`copyFiles` and `cutFiles` ignored the pasteboard write result, and file drops used `try?`, hiding copy errors. Copying after a cut could also leave the previous `openowl.fileCutPending` flag behind, causing a later paste to behave like a move.

**Fix:** Copy clears any old cut state before writing to the pasteboard. Copy and cut now surface pasteboard failures through `errorMessage`, and drag-drop copy errors are collected and shown instead of being swallowed.

### Files panel could visually overlap terminal content and manual resizing could reflow output

The v1.1.0 Right Dock animation fix froze the terminal view width while the dock opened to avoid destructive PTY reflow. That protected scrollback, but the Metal-backed terminal view could still retain its old wider frame during the transition, so terminal content appeared underneath the Files/Git panel.

Runtime logs later showed another path: resizing the UI manually was not frozen, so openOwl sent intermediate terminal sizes such as 56 → 72 → 104 columns while the user dragged. Long terminal output was then rewrapped at each intermediate width.

**Fix:** The terminal view frame now always clips to the current host bounds. During dock expand/collapse animation, manual resize-handle dragging, and AppKit window live resize, openOwl suspends non-forced PTY resize syncs instead of keeping the view wider than its container or syncing every intermediate width. The `TerminalNSView.setFrameSize` auto-sync path is suppressed during the freeze as well, and when the freeze ends, a forced `resize-freeze-ended` or `live-resize-ended` sync updates libghostty to the final size. Collapsing the dock or entering dock fullscreen now explicitly ends an interrupted interactive resize; normal drag end still releases it immediately.

### Terminal output felt slower while diagnostics were enabled

Recent runtime logs showed no terminal input errors and no sustained surface-size sync storm, but they did show repeated `ScrollView.layout ... changed=no` diagnostics during normal terminal activity. That path called `AppLogger.log`, which also calls `NSLog`, from inside the terminal layout hot path.

**Fix:** `TerminalScrollView.layout` now writes `resize-diag` only when the terminal view size actually changes. No-op layouts no longer write to Console.app or the file log.

### ESC could stop working and stale Kitty keyboard mode could print CSI-u text

After a Right Dock switch or SwiftUI view rebuild, the first responder could be a hosting/container view. The terminal fallback rejected that responder, so ESC never reached the focused pane. Separately, a TUI that exited without popping Kitty keyboard mode could leave the flag stack active and make later shell input appear as text such as `9;1:3u`.

**Fix:** Terminal fallback now distinguishes visible text/list input from command controls and stale responders: attached text fields, text views, and list content retain ESC, while buttons, hosting/container views, and hidden or detached responders allow delivery to the current visible terminal pane. Modal windows and non-terminal key windows never route ESC to a terminal behind them. Routing decisions are recorded under the `keyboard-routing` log tag for intermittent-focus diagnosis. Ghostty now clears the active screen's entire Kitty keyboard flag stack only at an explicit shell-integration `prompt_start`; it does not clear at command end, focus changes, or pane reattach, and it preserves the screen and scrollback.

### Persisted Right Dock width could crowd the terminal on narrower windows

Right Dock width is persisted as a user preference. If the user previously resized the dock on a wide window, that stored width could be too large after launching or resizing to a narrower window.

**Fix:** Normal dock width is now clamped to 50% of the current host width minus the rail. Fullscreen mode still fills the available space; list-only mode also respects the current-window clamp.

### Duplicate worktree archive requests could race

Project Rail and Project Session List previously allowed the same worktree to start multiple archive operations. Concurrent `git worktree remove --force` calls could leave one request reporting failure after another had already completed.

**Fix:** Both entry points now share a per-worktree in-flight guard in `ProjectStore`. The active action displays `Archiving...` and is disabled; duplicate requests for the same worktree are rejected, while different worktrees can still archive independently. The guard is released after success, failure, or cancellation so the operation can be retried.

Async worktree creation now runs editor preflight before the first Git side effect. After Git succeeds, the worktree is registered inactive; the later activation performs a second preflight. If the worktree being archived is active, preflight and the switch to its parent both happen before any `await`, Git command, or file move. A failed dirty-buffer save cancels the archive without Git/file side effects, and an in-flight archive cannot be reactivated.

### An unreadable project store could be overwritten

If `~/.openowl/openowl.json` could not be read or decoded, startup could continue with an empty list and later overwrite the original file.

**Fix:** openOwl first quarantines the unreadable file and asynchronously reports its backup location. If quarantine itself fails, the original file stays in place and the session's project store becomes read-only; all later persistence is refused and an asynchronous warning explains how to recover.

Project monogram palette selection also uses the hash magnitude, avoiding the `abs(Int.min)` overflow edge case.

### Git history ref badges wrapped incorrectly

Long branch and tag labels in Git history could wrap into multiple lines and distort row height.

**Fix:** Ref badges now remain single-line and truncate within the available history row width.

## Internal Improvements

- Added `FileEditorDiskSignatureProvider` and regression coverage for signature changes after file writes.
- File reads are scoped by URL, request identity, project session, and disk signature; pending tab activation is no longer shared with reload state.
- File Explorer remains mounted when the dock is collapsed; unsaved tab names are aggregated by editor/window token, view disappearance removes only its own token, and `AppDelegate` reads the flattened, sorted computed list.
- All three editor save exits share `saveTab`, which directly compares the opened and current disk signatures; automatic restore/reload has explicit 50 MB text/image boundaries.
- Reload paths update image and text tab signatures after load, restore, reload, save, save-all, close, and LRU eviction.
- Active text reloads swap in a fresh storage and rebuild the editor; the caret is clamped and restored, scroll and focus are not.
- Right Dock width clamping is centralized in `RightDockStore.maxNormalWidth(hostWidth:)`.
- Right Dock resize-handle drag state is tracked separately so terminal PTY resize freezes until drag end; AppKit live-resize also syncs only at the final size.
- Resize diagnostics now distinguish frozen layout from actual surface-size syncs, and no-op terminal layouts are no longer logged.
- Worktree archive state is serialized per worktree in `ProjectStore` and shared by both rail/session-list entry points.
- File Explorer and Right Dock docs were updated to match the new refresh and resize behavior.
- Added responder-policy coverage for terminal ESC fallback, including modal windows, command buttons, and stale hidden/detached responder cases, plus Ghostty regression coverage for stale Kitty keyboard state at the prompt boundary.

## Install

After the v1.1.1 GitHub Release is published, download `OpenOwl-1.1.1.dmg` from the [release page](https://github.com/sanvibyfish/openowl-app/releases/tag/v1.1.1), double-click to mount, and drag **OpenOwl.app** to Applications.

The final DMG must be rebuilt from the current v1.1.1 commit, then signed, notarized, stapled, and validated by Gatekeeper before publication.
