# openOwl v1.1.3 Release Notes

**Release Date**: 2026-08-03

Terminal workspace release. v1.1.3 restores the ability to deactivate a project by closing its terminals — broken in v1.1.2 — and gives the existing pane maximize feature a mouse entry point on the split handle.

---

## New Features

### Double-click the split handle to maximize / restore

The three-dot handle above each pane now toggles maximize on double-click. The capability itself is not new — `maximizedPaneID`, the render path, the menu item (Terminal → Maximize Pane) and ⇧⌘↩ have all shipped for several versions — but the only way to reach it was the keyboard, so most users never found it. Dragging a pane to rearrange it still works exactly as before.

Two supporting changes made this possible:

- **The handle now stays on screen while maximized.** It previously rendered only when `isMultiPane && !isMaximized`, so maximizing made the handle vanish and left the mouse with no way back. While maximized it drops `.onDrag` — reordering is meaningless with one pane on screen — and keeps the double-click.
- **`toggleMaximizeCurrentPane` takes an optional `paneID`.** The handle belongs to a specific pane, which is not necessarily the focused one; clicking a pane's handle now maximizes *that* pane. Passing nil keeps the old focused-pane behavior for ⇧⌘↩ and the menu.

Maximize does not touch the split tree: sibling panes keep their surfaces alive, their shell processes running, and their PTY dimensions unchanged, so a `vim` or `htop` in a hidden pane does not reflow. Restoring brings back the exact ratios that were dragged.

---

## Bug Fixes

### Project switching no longer flashes the terminal

Terminal tabs from every namespace now remain mounted for the lifetime of their session. Switching projects changes visibility instead of removing one `TerminalNSView` hierarchy from the window and reattaching another. Inactive tabs still pause their Metal layers, ignore input, and stay out of the accessibility tree.

This keeps the retained shell/session model and the retained AppKit view hierarchy aligned: the surface is destroyed only when its pane or tab is actually closed.

### Hidden panes no longer remain available to accessibility

Maximized sibling panes and inactive project tabs are explicitly hidden from system accessibility features as well as mouse hit testing. VoiceOver no longer encounters a handle or terminal that is mounted but invisible.

### A project could no longer be made inactive

Closing a project's terminals is how a project goes inactive and drops off the rail — the sidebar derives "active" by asking `TerminalWorkspaceStore.hasTabs`, there is no stored flag. In v1.1.2 that became impossible: `closeCurrent()` seeded a replacement tab the moment a namespace emptied, so `hasTabs` was permanently true and the project never left the rail.

That seeding was itself a fix (`82a8a8c`) for a real problem — falling back to `tabs.last` handed the active slot to another namespace's tab, and the `didSet` then overwrote that namespace's remembered tab position with one the user had never opened. The replacement tab avoided that, at the cost of this feature.

**Fix:** `closeCurrent()` now clears `activeTabID` and returns a new `.projectEmptied` action instead of seeding a tab. `AppDelegate` moves the sidebar selection to the free terminal. Both conditions must fall away for the project to actually disappear — leaving it selected would have the next `syncActiveProjectContext` seed it a tab through `switchNamespace`, undoing the close. The namespace-crossing bug stays fixed: the active slot is never handed to a foreign tab.

The transition is transactional: `closeCurrent()` asks the host to approve the project deactivation before destroying the final surface. If an editor cannot save a dirty tab and rejects the context change, the terminal session and project selection both remain intact.

Free terminals are unaffected and keep the ghostty rule — their last tab closes the window.

## Behavior Changes

| | v1.1.2 | v1.1.3 |
|---|---|---|
| ⌘W on a project's last terminal | A fresh tab appears in the same project | Project goes inactive and leaves the rail; selection moves to the free terminal; a rejected editor context change leaves the terminal open |
| ⌘W on the free terminal's last tab | Window closes | Unchanged |
| Split handle while maximized | Hidden | Visible; double-click restores, drag disabled |
| Switching projects | Terminal view can flash during AppKit detach / reattach | Existing terminal views remain mounted; only visibility changes |

The first row reverses v1.1.2's smoke test #8. That entry documented the seeding behavior as intended — it was the workaround, not the goal.

## Housekeeping

- The two ⌘W entry points (Close Tab menu item and the `NSEvent` local monitor) were duplicating the same close-and-dispatch logic; both now call one `closeCurrentTerminal()`.
- Docs corrected where they had drifted from the code: FEAT-006 described the rail as *ordering* projects with open tabs first and dimming the rest, but `railProjects` filters — projects without tabs are not on the rail at all.
- Removed unused compatibility views and legacy Git/Quick Open/terminal helpers that had no callers.

---

## Tests

372 tests pass. New coverage:

- A project namespace emptied by ⌘W reports `.projectEmptied`, keeps no active tab, and leaves another namespace's remembered tab position untouched
- A project with several tabs closes them one at a time; only the last empties the namespace
- The free terminal's last tab still returns `.closeWindow`
- Double-clicking a non-focused pane's handle maximizes that pane, not the focused one
- The split tree is byte-identical before maximize, during, and after restore
- A rejected project-deactivation approval preserves the last tab and does not destroy its surface
- An approved project deactivation commits the free-terminal selection and terminal removal together

## Install

After the v1.1.3 GitHub Release is published, download `OpenOwl-1.1.3.dmg` from the [release page](https://github.com/sanvibyfish/openowl-app/releases/tag/v1.1.3), double-click to mount, and drag **OpenOwl.app** to Applications.
