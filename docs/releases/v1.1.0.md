# openOwl v1.1.0 Release Notes

**Release Date**: 2026-06-16

Editor tab session persistence, editor-only layout, and a broad reliability sweep for terminal copy/paste, ESC/Ctrl+C routing, and scrollback during Right Dock animation.

---

## New Features

### Editor tab session persistence

Open editor tabs (text files and images) now persist per-project. Closing and re-opening the app, or switching between projects, restores the exact tab set and the active tab.

- Persisted per-project via `UserDefaults` under a stable key
- Encode/decode is cached in memory; only the encode + flush hits `UserDefaults`, eliminating the per-edit JSON decode hit
- Saves are debounced (200ms) and flushed eagerly on `onDisappear` or project switch
- Restore is resilient: an image that fails to decode or a file that fails to read is removed from the restored set instead of mounting a broken/empty editor

### Editor-only layout

Files dock now has a sidebar-hidden mode that shows only the active editor (no file tree). A toolbar button in the sidebar restores the tree. QuickOpen always opens results in the file explorer tab so it works identically in both layouts.

### Quieter, more reliable Cmd+V into the terminal

Cmd+V now reads `NSPasteboard` synchronously and injects via `ghostty_surface_text` directly. The previous binding-action path (`paste_from_clipboard`) depended on `read_clipboard_cb` → `activeSurface` → async completion, which silently failed when `activeSurface` was nil — common right after a dock toggle. File URLs from the clipboard are shell-escaped through a shared helper used by both drag-drop and paste.

## Bug Fixes

### Terminal scrollback corrupted while the Right Dock animated

Expanding or collapsing the Right Dock animates the terminal width over ~250ms, firing ~18 `setFrameSize` calls. Each one previously triggered `ghostty_surface_set_size` → `SIGWINCH`, so the shell re-wrapped its output at every intermediate column count (e.g. 115 → 26 → 115) and the scrollback ended up garbled.

**Fix (two layers):**
1. Non-forced `syncSurfaceSize` calls are debounced by 100ms — only the final size reaches libghostty, so the shell sees a single `SIGWINCH` instead of 18. Forced syncs (visibility restore, backing-scale change, surface creation) bypass the debounce for immediate correctness.
2. While the dock is animating, terminal frame width is frozen behind a transient `isAnimatingDockResize` flag that auto-clears after 400ms — this prevents the destructive narrow → wide reflow entirely. After the flag clears the terminal resumes normal resizing.

Also: `syncSurfaceSize` early-exits when the backing size hasn't changed, avoiding ~60 `DispatchWorkItem` allocations/sec during interactive resize.

### ESC and Ctrl+C often didn't reach the terminal

After a Right Dock tab switch, `firstResponder` was frequently an `NSHostingView` or other SwiftUI-internal view rather than `TerminalNSView`. The old guard (`firstResponder is TerminalNSView`) returned false for these and dropped the key silently. A secondary failure mode: when the target `TerminalNSView` was already first responder but `activeSurface` pointed elsewhere, `makeFirstResponder` no-op'd and `becomeFirstResponder` never fired, leaving `activeSurface` stale.

**Fix:** The fallback routing in `AppDelegate.performKeyEquivalent` now inverts the check — only text input controls (`NSTextView`, `NSTextField`, `NSOutlineView`) block routing; everything else (including bare `NSWindow` and SwiftUI hosting views) falls through to the terminal. New `ensurePaneFocused()` directly assigns `activeSurface` and only calls `makeFirstResponder` when the view isn't already the responder. The check itself is now based on local responder state (`window.firstResponder === self`) instead of the global mutable `activeSurface` singleton, eliminating race conditions during focus hand-off between panes.

### Cmd+V/C/F/P also blocked after dock state changes

The same strict responder guard that fixed earlier ESC issues was over-aggressively gating every Cmd shortcut, blocking copy/paste in the terminal whenever `acceptsTerminalKeyboardInput` returned false. Now only ESC requires the strict acceptance check; Cmd+V/C/F/P use the lightweight `firstResponder` guard alone.

### PTY size sync during hidden terminals

When a terminal pane was momentarily 0×0 or 1px during layout transitions, the sync still fired and resized the PTY to a useless dimension, which the shell then remembered. Hidden/degenerate sizes are now skipped, and a forced resync runs on visibility restore so the pane comes back at the correct size.

### Tab-restore could overwrite a file or store a broken cache entry

If a persisted editor tab pointed at a file that failed to read, the editor opened empty — and saving from that empty buffer would overwrite the on-disk file. Image tabs that failed to decode were caching `nil`. Both paths now drop the affected tab from the restored set and log the failure via `AppLogger`.

### Git worktree removal failed when `.DS_Store` was present

Worktree removal previously fell back to `rm -rf` + `git worktree prune` on any error. Now it falls back **only** on a `"not empty"` error (the canonical `.DS_Store` case on macOS) and re-throws everything else, so genuine failures aren't masked.

## Internal Improvements

- `TerminalWorkspaceStore.activeFocusedPaneID` extracted; replaces 4 copies of the tab+pane resolution pattern in `AppDelegate`
- `AppDelegate` checks `keyCode` before touching the store in fallback routing, skipping property lookups for 99%+ of `keyDown` events
- `GhosttyApp.ensurePaneFocused` simplified to delegate to `focusPane`
- `syncSurfaceSize` guard-and-log blocks collapsed (25 → 10 lines) via a `logSkip` closure
- `RightDockStore` validates `filesShowsTree` / `filesShowsEditor` after init to prevent the illegal `(false, false)` state from corrupted `UserDefaults`
- Dead `RightDockStore.showsListForActiveTab` removed
- Silent `try?` in editor session persistence replaced with `do/catch` + `AppLogger`
