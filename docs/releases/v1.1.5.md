# openOwl v1.1.5 Release Notes

> **Status**: ⤴️ Merged | **Notes Ready**: 2026-08-10 | **Released**: never released on its own — folded into [v1.1.6](v1.1.6.md)
>
> This version was never tagged. Everything described here shipped in v1.1.6; the file is kept as a record.

Right Dock correctness and terminal automation release. v1.1.5 keeps file contents, Git state and asynchronous results attached to the repository and selection that produced them, hardens file-operation lifecycles, and adds Ghostty-style AppleScript control for native terminal tabs and panes.

---

## New Feature

### Terminal automation through AppleScript

macOS automation clients can now query openOwl windows, tabs and terminals by stable ID, then create tabs, split panes in four directions, focus targets, inject text and close terminals. Optional surface configuration supports working directory, command, initial input, environment variables and font size. The implementation uses openOwl's existing workspace and pane lifecycle, including editor vetoes and namespace boundaries.

## Bug Fixes

### Right Dock files reload promptly and safely

- File-watcher events now reload every open, clean editor tab whose disk signature changed instead of waiting for the user to switch tabs.
- Dirty buffers remain untouched, and stale or failed reads cannot advance the tab's disk signature or overwrite a newer request.
- Project changes discard stale tree scans, Quick Open results and editor completions before they can appear under the new project.

### Git diff and graph state stay with their source repository

- Repository identity is resolved from the real Git root, including nested repositories and submodules. Status, log, commit draft, selection, diff and errors no longer leak across repository switches.
- Workspace and commit diff requests use repository, revision and selection ownership checks, so a late success or failure cannot replace the user's newer selection.
- Switching commits resets file expansion, selection and scroll position. Git Graph pagination, root commits, empty repositories and commit-detail loading/error states remain isolated and deterministic.

### Git operations handle conflicts and unusual repositories correctly

- Stage All uses `git add -A`; Unstage works before the first commit; unborn branch headers show the actual branch name and Graph displays `No commits yet` without an error.
- All seven unmerged status forms are grouped as conflicts. Commit, auto-stage commit and Discard All reject unresolved conflicts before changing markers, the index or status.
- Discard All restores tracked files to the current index, preserves staged and ignored content, and removes non-ignored untracked files, directories and nested repositories.
- Git C-style quoted paths, UTF-8 octal escapes and renamed files whose names contain ` -> ` are decoded consistently in status and commit diffs.

### File operations preserve editor-tab lifecycles

- Rename and cut/move atomically migrate open-tab state to the new URL, including directory descendants and in-flight initial reads. Destination collisions are rejected before touching disk.
- Partial multi-file moves retain only failed items for retry. Delete immediately prunes tree, search, selection, preview and Quick Open state.
- In-app deletion refuses dirty files and closes clean tabs after success. External deletion closes clean tabs but preserves dirty in-memory buffers and reports the missing backing file.
- The Rename field now uses the system text background and control text colors. Enter and Escape both restore the normal file-row appearance, so the edit background does not remain after rename ends.
