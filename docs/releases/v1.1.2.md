# openOwl v1.1.2 Release Notes

**Release Date**: 2026-08-01

Design consistency and reliability release. v1.1.2 unifies the selection chrome across every list in the app, rewrites the Git diff view as unified single-column with word-wrap, fixes the persistent Documents-folder permission prompt on Debug builds, adds terminal tab memory across project switches, and removes the broken bell notification chain.

---

## New Features

### Unified selection chrome

All list rows — sidebar sessions, Git changed files, commit graph, Quick Open, and the AppKit file tree outline — now share the same selection style: a 2pt accent-color left bar with a 12% accent fill on a rounded background. The tokens live in `SelectableRowMetrics` and are consumed by both a SwiftUI modifier (`selectableRowChrome`) and an AppKit `NSTableRowView` subclass (`AccentBarTableRowView`), so the two rendering paths cannot drift apart on geometry or opacity.

### Terminal tab memory

Each terminal namespace (project or free terminal) remembers which tab was last active. Switching away from a project and coming back now lands on the tab the user left off on, rather than always resetting to the first. The record is written from `activeTabID`'s `didSet` and verified before restore — a closed tab falls back to the first tab as before.

### Cmd+T scoped to free terminal

Project namespaces do not draw a tab bar, so a project tab had no visible entry point — Cmd+T created it and made it active, leaving no way back except clicking a pane row in the sidebar. The menu item is now grayed out and the keyboard monitor gated when a project is active. Free terminals are unaffected.

## Bug Fixes

### Documents-folder permission prompt kept reappearing

Debug and Release builds shared the same bundle ID (`com.openowl.app`). macOS keys TCC grants by bundle ID plus the signing requirement recorded at grant time, so running one build after the other invalidated the permission and re-prompted. Debug now builds as `com.openowl.app.dev` with a separate TCC record. The override is in `project.yml` so `xcodegen generate` preserves it.

### Editor undo stack lost on dock collapse

The editor was unmounted when the dock collapsed to width 0 (via a `GeometryReader` size guard), and remounted on expand — which rebuilt the `NSTextStorage` and cleared the undo history. The editor now stays mounted unconditionally. `EditTracker.destroy()` no longer clears the shared `controller` reference (which was the live one, not the dying one). Relayout is consolidated to `EditorBoundsObserver` as the sole post-layout trigger.

### Resize handle unresponsive after upgrade

The drag gesture anchored to `dock.width` (a stored preference), but `effectiveWidth` could floor it upward — an install carrying the old 420pt default rendered at 520pt. Dragging narrower proposed values below the floor, so every one was clamped and the handle did nothing. It now anchors to the width actually on screen.

### Commit diff expanded another file's contents

The "expand unmodified lines" feature read the file off disk via `selectedChange`, but `selectCommit()` did not clear `selectedChange`. Selecting a working-tree file, then a commit, then expanding a hunk in a different file would splice in the first file's current contents — line-numbered and syntax-highlighted against the second file's hunk, with nothing to signal it. A deleted file's `@@ -1,N +0,0 @@` could also crash via `ForEach(1..<0)`.

**Fix:** Commit diffs no longer offer expansion (the correct source is `git show <hash>:<path>`, not the disk file). Staged diffs are also gated — `git diff --staged` compares HEAD against the index, and the disk copy can be ahead. Only the working-tree section allows expansion.

### Diff parsing errors

Three issues in `parseUnified`, all pre-existing but now addressed:
- A trailing newline produced a phantom blank context row on every diff and inflated the "N lines" badge.
- `\ No newline at end of file` rendered as file content and pushed `prevNewEnd` forward, making the next hunk under-count its skipped lines.
- Expanded rows fed the new line number to both old and new columns; the old column now derives from the hunk's old/new start offset.

### SPM patch script only reached one checkout

`apply-spm-patches.sh` took the first `Typesetter.swift` it found and exited 0 when it found none. In practice it patched the in-repo DerivedData and left Xcode's default one untouched — so Cmd+R builds still had the soft-wrap redraw bug. It now patches every openOwl DerivedData checkout (scoped to `openOwl-*` to avoid corrupting other projects), exits 1 on failure, and is documented in CLAUDE.md.

### closeCurrent() corrupted terminal tab memory

When a namespace's last tab was closed, the fallback `visible.first ?? tabs.last` handed the active slot to another namespace's tab. The new `activeTabID.didSet` then overwrote that namespace's remembered position with a tab the user had never opened. The fallback now seeds a fresh tab within the current namespace instead.

### File-read failure rendered as permanent spinner or silent no-op

`FileLinesState` now carries a descriptive error message in `.failed(String)` and renders in-place as a retry row. Previously: the sentinel empty array could not distinguish "loading" from "failed", failure borrowed `store.errorMessage` which `refresh()` clears on any FileWatcher tick, and the view had no `.failed` branch — so the one signal of failure could vanish before being read, and the UI returned to "nothing happened".

## Removed

### Bell notification chain

The entire bell path has been removed: `paneBellStates`, `handleBell`, `clearBell`, `bellCount`, sidebar pane bell indicators, rail/session unread badges, alert sound, dock bounce, system notification, and the Settings > Notifications section. The implementation did not work well enough to keep while notifications get rethought. The ghostty-side `RING_BELL` action is explicitly swallowed to prevent a system beep.

## Install

After the v1.1.2 GitHub Release is published, download `OpenOwl-1.1.2.dmg` from the [release page](https://github.com/sanvibyfish/openowl-app/releases/tag/v1.1.2), double-click to mount, and drag **OpenOwl.app** to Applications.
